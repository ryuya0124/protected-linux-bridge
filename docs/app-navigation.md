# Material 3画面構成

Android 17版alpha.2で、常設の操作ボタンを並べた構成から、下部ナビゲーションと設定項目の一覧・詳細へ整理しました。Material 3のBottomNavigationView、MaterialToolbar、Card、Switch、選択メニューとテーマ色を使います。独自描画のタブは使いません。

| 画面 | 対象と役割 |
| --- | --- |
| 概要 | ホストの識別、Debianの起動支援の状態、ターミナル／デスクトップへの接続 |
| VM | Debianの導入・画面・リソース・ディスク・ゲストカーネル。Androidゲストは独立した利用不可の項目 |
| デバイス | DebianとホストAndroidの通信、音声・マイク、クリップボード |
| 設定 | アプリ全体のデータ、任意の標準ターミナル連携、説明・ライセンス |

各詳細画面には「Debian · 音声とマイク」など対象を付けます。詳細で戻ると親タブへ戻り、設定の詳細を別タブの状態と混ぜません。標準ターミナルへのVector適用状況は、その任意連携の画面に置きます。Bridge内の利用にVectorは必須ではありません。

バックアップはチェック可能な4枚のカードを選び、画面下の主操作から実行します。回復・説明は右上メニュー、停止は状態カード内の副操作、キャンセルは実行中だけ表示します。文字を拡大した場合や狭い画面ではカードを1列にし、選択は画面再生成でも保持します。

Debian導入はイメージの種類・ARM64・必要容量と1つのダウンロード操作を中心にし、既存イメージの取り込みは別の一覧項目にします。ストレージ一覧もDebian／Androidゲスト／アプリ全体へ分けます。ディスクの変更は操作の選択メニューと必要な入力欄にまとめました。

## 検証の区別

- 開発Macの専用API 37 ARM64エミュレーターで、4タブ、詳細と戻る、バックアップ選択、Debian導入画面、ディスク操作メニューを操作確認。
- 英語・日本語、ライト／ダーク、文字倍率1.4、縦／横の再生成を確認。対象外ホストでは起動拒否の状態を表示。
- エミュレーターではVMやGPUは起動していません。GalaxyのGUIは操作していません。
- Galaxyの非GUI試験は[バックアップ記録](backup-and-restore.md)と[Android 17移植記録](android17-port.md)を参照。画面操作や通常VMセッションの検証を意味しません。
