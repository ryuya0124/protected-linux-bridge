# Protected Linux Bridge

Android標準の「ターミナル」から、Snapdragon / Gunyahの保護VM上でDebianを使う実験用モジュールです。一時rootとVectorを利用し、端末に元からあるカーネルで動かします。

**カーネル更新、ブートローダーアンロック、パーティション書き換え、端末再起動、SELinux設定変更は行いません。**

## できること

- 標準ターミナルの画面でDebianシェルを操作
- 複数タブで独立したシェルを使用
- 専用ディスクにファイルや追加パッケージを保存
- `curl`・`apt`など、プロキシ対応ツールでHTTP/HTTPS通信
- GUI（TigerVNC / Openbox / xterm）を表示・操作し、Bridge内の全画面表示とターミナルを併用
- アプリからGPUのオン／オフ、9種類の解像度、15〜120 fpsの更新上限を選択
- マウス・物理キーボード用の入力経路（実機のUSB/Bluetooth機器は未検証）
- 任意でOpenGLとWestonの画面合成を端末のAdreno GPUへ転送（VirGL / VTest）
- 指定した宛先へのUDP転送と、実際のIPv4 ICMP/ping
- アプリのボタンで標準ターミナルを有効化し、Linuxインストール画面を起動
- root要求、Vectorの状態表示、接続のオン／オフ、VMと起動支援の停止

Android上のchrootやPRootではなく、独立したカーネルの実行インスタンスを持つVMです。Android本体のカーネルは変更せず、端末に元からあるAVF用Microdroidカーネルファイルをゲストとして起動します。新しいカーネルの取得・追加・交換も行いません。ただし、この経路は **pvmfwによる検証済み起動・アテステーションを提供しません**。通常の検証済みAVFゲストと同じ保証はありません。

## 対応条件

実機確認済みなのは **Galaxy S26 Ultra SM-S948Q / Android 16 / 標準Terminal versionCode 36** です。すべてのSnapdragon端末に対応するものではありません。未確認のOS・Terminalバージョンではフックを停止します。

- Gunyah保護VMに対応し、既存のMicrodroidカーネル・crosvmを含む端末
- `su -M` を使えるroot環境（一時root可）
- Vector / libxposed API 102
- 標準ターミナルと、標準インストーラーが取得したLinuxイメージ
- 主ユーザー（user 0）
- 起動時に1.5 GiB以上の利用可能メモリ、初回に約3 GiB以上の空き容量

## 導入

1. 署名済みrelease APKをインストールします。
2. アプリを開き、root要求を許可します。「標準ターミナルを有効化」「Linuxインストール画面を開く」で標準機能を準備します。Linuxが未導入なら標準インストーラーで取得します。
3. Vectorでモジュールを有効にし、適用先に **ターミナル (`com.android.virtualization.terminal`) だけ**を選びます。Androidシステムは不要です。
4. アプリへ戻り「VM起動支援を準備」→「標準ターミナルを開く」を押します。起動中だったターミナルは開き直してください。
5. 初回は標準Linuxイメージを専用領域へコピーするため、少し時間がかかります。元のイメージは変更しません。

GUIを追加するには、ターミナルを前面にした状態で次を実行します。

```sh
plb-install-gui
```

完了後、ターミナル右上の画面表示ボタン、またはBridgeの「GUIを全画面で開く」を押します。全画面GUIを閉じても、既存のターミナルタブは終了しません。最後の接続を閉じるとVMは停止します。ゲストのxtermをタップしてから、下の入力欄に文字を入れて「送信」、または「Enter」で送信・実行できます。戻る操作でシェルへ戻ります。GUIを使わなければ追加パッケージは不要です。

## GPU描画

GUI導入後、Linux内で実行します。

```sh
plb-install-gpu
```

アプリの「LinuxのOpenGLをGPUで描画」「WestonでデスクトップをGPU合成」をオンにし、「保存してVMだけ作り直す」で反映します。Linuxの作業は先に保存してください。**Androidの再起動は不要です。** 以後のシェルとGUIにOpenGL用のGPU設定を渡し、表示ボタンからGPU合成のWestonデスクトップを開きます。

```sh
plb-gpu-info                 # 描画ドライバーの確認
plb-gpu-run glxinfo -B        # 個別にGPUを指定して起動する例
plb-gpu-mode off              # CPU描画へ戻す（VMを作り直して反映）
plb-gpu-mode on               # 再びGPU描画を有効化
plb-desktop-mode classic      # 元のOpenboxデスクトップへ戻す（VM再作成で反映）
plb-desktop-mode gpu          # WestonのGPU合成へ切り替え（同上）
```

Bridgeで描画設定を保存した後は、VM起動時にアプリの設定が下記コマンドの指定より優先します。

実機で `virgl (Adreno (TM) 840)`、OpenGL ES 3.2、OpenGL 2.1、GLXの `Accelerated: yes` と実描画を確認しています。Westonはウィンドウの画面合成にGPUを使います。アプリ自体の2D描画はアプリによって異なります。「転送画面をOpenGLで直接表示」をオンにすると、生の画素をDirectByteBufferで受け取り、GLESのテクスチャへアップロードしてGPUで拡大・合成します。VNCの画像圧縮・JavaScriptでの展開を省きますが、**画面取得・転送・コピーにはCPU処理が残ります。ゼロコピーではありません。** オフでは従来のnoVNC互換表示を使います。切り替えは表示を開き直すと反映し、VMの作り直しは不要です。 GPU VulkanやGPUパススルーには対応しません。Venusの共有メモリー経路には別途実装が必要です。重いアプリが快適になるとは限らず、対応するGLの機能にも制限があります。問題があればCPU描画へ戻せます。GPU描画は追加パッケージを導入するまで無効です。

## 解像度・更新上限・入力

Bridgeの「GUIの解像度」「GUIの更新上限」で選択し、「保存してVMだけ作り直す」で反映します。Android本体の解像度やリフレッシュレートは変更しません。

- 横長: 960×540、1024×768、1280×720、1280×800、1600×900、1920×1080、2560×1440
- 縦長: 720×1280、1080×1920
- 更新上限: 15 / 24 / 30 / 60 / 90 / 120 fps（初期値1280×720 / 30 fps）

これは要求する更新上限であり、常時そのfpsで動く保証ではありません。画面の実際のHz、ゲスト描画、転送帯域、メモリで制限されます。高解像度・高fpsほど負荷が上がります。画面サイズと上限はVMのXvncへ、fpsは直接表示側へも渡します。Westonやアプリ独自の描画上限は別です。直接表示は画面変更に応じて更新し、静止中に定期ポーリングしません。

直接表示のLinux画面をタップすると物理キーボードの入力先になります。修飾キー、矢印、F1〜F12、マウスの左右・中央ボタン、ホバー、縦横ホイールに対応する経路を用意しています。Androidの戻る・ホーム・音量キーはAndroid側に残します。日本語などAndroid IMEでの変換入力は「入力・操作」の入力欄から送信します。**物理USB/Bluetoothキーボード・マウスでの動作は未検証です。**

## sudoとAndroid本体の保護

現在のDebianシェルはVM内のrootです。`sudo`は導入済みで、`sudo -n id`の成功を確認しています。一般ユーザーのsudoers設定は別途必要です。VM内のrootはAndroidのrootではありません。

AndroidのファイルやGPUデバイスをLinuxへ直接共有しません。GPUコマンド処理は非rootプロセスに分離しています。ただし、**現状のホストcrosvmはrootかつ標準プロセスサンドボックスなしで動く実験経路**です。pvmfwの検証済み起動・アテステーションもありません。悪意あるLinuxソフトからAndroid本体を完全に保護する用途には適しません。[保護境界と確認した制限](docs/security.md)を参照してください。

## UDPとping

```sh
ping -c 4 1.1.1.1
plb-udp-forward 5353 1.1.1.1 53
```

`ping` はホスト側の非特権ICMPソケットを使って実際のIPv4 echoを送ります。表示するRTTにはVMとの転送時間も含みます。IPv6 pingやrawソケットは提供しません。Androidがping用ソケットを禁止している環境ではエラーになります。システム設定を変えて解除しません。

`plb-udp-forward` はゲストの `127.0.0.1:5353` に届くUDPを `1.1.1.1:53` へ転送します。利用するツール側もこのローカルポートへ接続する設定が必要です。別シェルタブで実行し、Ctrl+Cで終了します。宛先のホスト名・ポートは変更できます。同時に最大16クライアント、無通信60秒で関連付けを破棄、1回最大30分です。

仮想NICや透過的なIP接続ではありません。一般のLAN上の別ホストには接続できますが、ホスト自身・loopback・link-local・multicastなどは拒否します。UDPの外部からの着信待受は作りません。

## 保存・終了

専用ディスクへの変更はVMを終了しても残ります。タブの `exit` はそのシェルを終了します。1つのタブを閉じても他のタブは継続し、最後の接続が閉じるとVMを停止します。ホームへ移動するだけでは終了しない場合があります。

「VMと起動支援を停止」で全セッションを終了できます。先に作業を保存してください。再利用時は起動支援を準備し、ターミナルを開き直します。一時rootが失われた場合は既存のroot環境を復旧してから準備してください。本アプリはroot化を実行しません。

アプリのデータ削除・アンインストールでは専用Linuxディスクも消えます。必要なファイルは先にバックアップしてください。標準ターミナルの元イメージは別に保持されます。

## 制限

| 項目 | 現状 |
|---|---|
| VM | RAM 512 MiB、1 vCPU、1回最大30分 |
| シェル | PTY 80×24、同時接続はGUIを含め最大12 |
| 保存 | 約2.8 GiBのLinuxファイルシステム。容量変更UIは未対応 |
| ネットワーク | HTTP/HTTPS、明示的UDP転送、IPv4 echo。仮想NIC・透過的なIP接続は未対応 |
| ホストへの影響 | 通信・メモリ・ストレージは消費します。ルート・DNS・ファイアウォール設定は変更しません |
| 通信制限 | 標準ターミナルのUIDで通信し、アプリ別VPN・省電力制限に従います。バックグラウンドやDozeでは通信が止まる場合があります |
| GUI | 9解像度、15〜120 fps上限、全画面。OpenGLと画面表示はGPU化可能。取得・コピーはCPU。GPU Vulkan・音声は未対応 |
| 動作維持 | 起動支援の待機は最大30分。プロセス終了やroot喪失後は準備し直す必要があります |

標準のディスク設定はこの専用ディスクに適用できないため無効にしています。LinuxパッケージのインストールはVMの中だけで行われます。

## 無効化・復旧

1. 作業を保存し「VMと起動支援を停止」。
2. 接続スイッチをオフにし、ターミナルを閉じる。
3. Vectorでも無効にすれば標準動作に戻ります。

元の標準ターミナルが非保護VM非対応で落ちる端末では、無効化しても標準機能が使えるとは限りません。未対応のOS更新後にフックが止まった場合も、カーネル変更などで無理に回避しないでください。
