# Protected Linux Bridge

Android標準の「ターミナル」から、Snapdragon / Gunyahの保護VM上でDebianを使う実験用モジュールです。一時rootとVectorを利用し、既存Microdroidカーネルを標準で使い、独自Linuxゲストの実験用プロファイルも選べます。

**Android本体のカーネル・起動領域・SELinuxは変更しません。BLU・Android再起動も行いません。** ゲスト専用のカーネルはアプリのデータ領域へ追加できます。[変更しないホスト領域・禁止操作](docs/host-boundary.md)を明記しています。

## できること

- 標準ターミナルの画面でDebianシェルを操作
- 複数タブで独立したシェルを使用
- 専用ディスクにファイルや追加パッケージを保存
- `curl`・`apt`など、プロキシ対応ツールでHTTP/HTTPS通信
- GUI（TigerVNC / Openbox / xterm）を表示・操作し、Bridge内の全画面表示とターミナルを併用
- アプリからGPUのオン／オフ、9種類の解像度、15〜120 fpsの更新上限を選択
- マウス・物理キーボード用の入力経路（実機のUSB/Bluetooth機器は未検証）
- 任意でOpenGLとWestonの画面合成を端末のAdreno GPUへ転送（VirGL / VTest）
- 指定した宛先へのUDP転送と、実際のIPv4 ICMP/ping
- 実験用プロファイルで、アプリごとのプロキシ設定が不要なTCP・UDP・DNS通信
- アプリのボタンで標準ターミナルを有効化し、Linuxインストール画面を起動
- RAM・CPU・稼働時間・VM常駐の選択、1〜128 GiBのディスク拡張・縮小、空き領域の回収・前のディスクへの復元
- `systemd`をPID1として起動し、`systemctl`でサービス管理・自動起動
- スピーカー・マイクのAndroid経由中継、マイクのGUI限定／バックグラウンド継続
- クリップボードの手動共有、任意でバックグラウンド双方向共有
- 有線・USB・Bluetooth音声の接続先選択（実物の周辺機器では未検証）
- 既存Microdroidと、独立したディスクを使う実験用Linux 6.18ゲストの選択
- Android 17ゲストの画面表示プレビュー（1536MiB／未検証の1792MiB／従来の512MiBを選択。構成ごとにデータを保存します。事前準備・root・起動時の確認が必要。v0.4.0-preview.7はホストのページ管理エラーを検出すると大容量構成を起動しません。[使い方と制限](docs/android-guest-display.md#integrated-15-gib-selection-040-preview5)）
- Material 3の「ホーム」「画面」「連携」「設定」、root・Vectorの状態表示、VM停止

Android上のchrootやPRootではなく、独立したカーネルの実行インスタンスを持つVMです。Android本体のカーネルは変更せず、端末に元からあるAVF用Microdroidカーネルファイルをゲストとして起動します。実験用プロファイルでは、専用領域のLinux 6.18.57-plb1をゲストとして起動します。AndroidのAVBと、ゲストカーネルの起動は別です。ただし、この経路は **pvmfwによる検証済み起動・アテステーションを提供しません**。通常の検証済みAVFゲストと同じ保証はありません。

## 対応条件

実機確認済みなのは **Galaxy S26 Ultra SM-S948Q / Android 16 / 標準Terminal versionCode 36** です。すべてのSnapdragon端末に対応するものではありません。未確認のOS・Terminalバージョンではフックを停止します。

- Gunyah保護VMに対応し、既存のMicrodroidカーネル・crosvmを含む端末
- `su -M` を使えるroot環境（一時root可）
- Vector / libxposed API 102
- 標準ターミナルと、標準インストーラーが取得したLinuxイメージ
- 主ユーザー（user 0）
- 起動時に1.5 GiB以上の利用可能メモリ、初回に約3 GiB以上の空き容量

## 導入

1. 署名済みrelease APKをインストールします。
2. アプリを開き、root要求を許可します。「標準ターミナルを有効化」「Linuxインストール画面を開く」で標準機能を準備します。Linuxが未導入なら標準インストーラーで取得します。
3. Vectorでモジュールを有効にし、適用先に **ターミナル (`com.android.virtualization.terminal`) だけ**を選びます。Androidシステムは不要です。
4. アプリへ戻り「VM起動支援を準備」→「標準ターミナルを開く」を押します。起動中だったターミナルは開き直してください。
5. 初回は標準Linuxイメージを専用領域へコピーするため、少し時間がかかります。元のイメージは変更しません。

GUIを追加するには、ターミナルを前面にした状態で次を実行します。

```sh
plb-install-gui
```

完了後、ターミナル右上の画面表示ボタン、またはBridgeの「GUIを全画面で開く」を押します。全画面GUIを閉じても、既存のターミナルタブは終了しません。「すべて閉じてもVMを維持」がオフなら、最後の対話接続を閉じるとVMは停止します。ゲストのxtermをタップしてから、下の入力欄に文字を入れて「送信」、または「Enter」で送信・実行できます。戻る操作でシェルへ戻ります。GUIを使わなければ追加パッケージは不要です。

## GPU描画

GUI導入後、Linux内で実行します。

```sh
plb-install-gpu
```

アプリの「LinuxのOpenGLをGPUで描画」「WestonでデスクトップをGPU合成」をオンにし、「保存してVMだけ作り直す」で反映します。Linuxの作業は先に保存してください。**Androidの再起動は不要です。** 以後のシェルとGUIにOpenGL用のGPU設定を渡し、表示ボタンからGPU合成のWestonデスクトップを開きます。

```sh
plb-gpu-info                 # 描画ドライバーの確認
plb-gpu-run glxinfo -B        # 個別にGPUを指定して起動する例
plb-gpu-mode off              # CPU描画へ戻す（VMを作り直して反映）
plb-gpu-mode on               # 再びGPU描画を有効化
plb-desktop-mode classic      # 元のOpenboxデスクトップへ戻す（VM再作成で反映）
plb-desktop-mode gpu          # WestonのGPU合成へ切り替え（同上）
```

実験用プロファイルでは「軽量GPU設定を適用」で、512 MiB・1 CPU・960×540・30 fps・Openbox＋GPUアプリ描画をまとめて選べます。VMだけを停止するため、適用後にGUIを開き直してください。この構成で実描画は確認しましたが、高負荷時のGunyahメモリ障害を解消したわけではありません。

Bridgeで描画設定を保存した後は、VM起動時にアプリの設定が下記コマンドの指定より優先します。

実機で `virgl (Adreno (TM) 840)`、OpenGL ES 3.2、OpenGL 2.1、GLXの `Accelerated: yes` と実描画を確認しています。Westonはウィンドウの画面合成にGPUを使います。アプリ自体の2D描画はアプリによって異なります。「転送画面をOpenGLで直接表示」をオンにすると、生の画素をDirectByteBufferで受け取り、GLESのテクスチャへアップロードしてGPUで拡大・合成します。VNCの画像圧縮・JavaScriptでの展開を省きますが、**画面取得・転送・コピーにはCPU処理が残ります。ゼロコピーではありません。** オフでは従来のnoVNC互換表示を使います。切り替えは表示を開き直すと反映し、VMの作り直しは不要です。 GPU VulkanやGPUパススルーには対応しません。Venusの共有メモリー経路には別途実装が必要です。重いアプリが快適になるとは限らず、対応するGLの機能にも制限があります。問題があればCPU描画へ戻せます。GPU描画は追加パッケージを導入するまで無効です。

## 解像度・更新上限・入力

Bridgeの「GUIの解像度」「GUIの更新上限」で選択し、「保存してVMだけ作り直す」で反映します。Android本体の解像度やリフレッシュレートは変更しません。

- 横長: 960×540、1024×768、1280×720、1280×800、1600×900、1920×1080、2560×1440
- 縦長: 720×1280、1080×1920
- 更新上限: 15 / 24 / 30 / 60 / 90 / 120 fps（初期値1280×720 / 30 fps）

これは要求する更新上限であり、常時そのfpsで動く保証ではありません。画面の実際のHz、ゲスト描画、転送帯域、メモリで制限されます。高解像度・高fpsほど負荷が上がります。画面サイズと上限はVMのXvncへ、fpsは直接表示側へも渡します。Westonやアプリ独自の描画上限は別です。直接表示は画面変更に応じて更新し、静止中に定期ポーリングしません。

直接表示のLinux画面をタップすると物理キーボードの入力先になります。修飾キー、矢印、F1〜F12、マウスの左右・中央ボタン、ホバー、縦横ホイールに対応する経路を用意しています。Androidの戻る・ホーム・音量キーはAndroid側に残します。日本語などAndroid IMEでの変換入力は「入力・操作」の入力欄から送信します。**物理USB/Bluetoothキーボード・マウスでの動作は未検証です。**

## 音声・クリップボード

GUIを導入したLinuxで `plb-install-integration` を実行します。「連携」タブで機能を選びます。

スピーカーはBridgeの全画面GUIで再生します。マイクは初期状態でオフ、Androidの権限が必要です。「GUI表示中のみ」か「バックグラウンドでも継続」を選べます。継続中はAndroidのマイク表示・停止できるサービスを使用し、rootで録音しません。GUIを閉じた後も継続させたい場合だけオンにしてください。

有線・USB・Bluetooth音声をLinuxに使うか、Android側に残すか選べます。オフではLinuxを内蔵スピーカー／内蔵マイクに限定し、オンでは接続済みの出力・入力を個別選択できます。機器の排他占有ではなく音声中継です。Androidアプリの経路やBluetoothペアリングを変更しません。未接続・複数候補・経路拒否はエラーにし、選択機器が外れたら中継を止めます。変更後はGUIを開き直してください。従来型BluetoothのマイクはAndroidが入力経路を公開している場合に限ります。**実物のイヤホン・USB音声機器での動作は未検証です。**

クリップボードは64 KiB以下のテキストを手動で送受信できます。自動共有は任意で、方向を選択できます。Androidのshell UIDが既に持つ背景読み取り権限を使い、機密指定テキストは送りません。履歴を保存せず、イベントで更新します。VM／起動支援を止めるとワーカーも終了します。先にLinuxのGUIを開いてください。

## VM設定・ディスク管理

「設定」でRAM、CPU、稼働時間、常駐、systemdを選択します。反映にはVMだけを作り直します。Linuxの作業は先に保存してください。Androidは再起動しません。

「設定」→「ディスク管理」では、1〜128 GiBの拡張・縮小、未使用領域の回収、前のディスクへの復元ができます。停止中のコピー上でファイルシステムを検査・変更し、読み戻し照合が通った場合だけ切り替えます。元のディスクは復元用として残し、明示的に削除するまで保持します。縮小先にデータや管理情報が収まらない場合は中止します。一時的な空き容量と処理時間が必要です。手動バックアップの代わりにはなりません。[容量表示の意味・操作方法](docs/storage.md)も参照してください。

systemdは実際のPID1で、`systemctl start/stop/enable`が使えます。Microdroidでは名前空間・seccompが不足するため、一部のサービス隔離設定をゲスト内で解除しています。実験用カーネルでもBPFなど未対応の機能は残ります。通常のDebianと同じ隔離保証はありません。aptで追加したゲストカーネルを自動的に起動する仕組みではありません。

## 実験用ゲストカーネル

通常はMicrodroidのまま使います。新しいプロファイルはLinux 6.18.57-plb1と、元のDebianをコピーした**別の永続ディスク**を使います。元のディスクは残り、コピー後の変更は同期しません。

1. [共通ゲストカーネル `Image-6.18.57-plb1`](https://github.com/ryuya0124/protected-linux-bridge/releases/download/v0.4.0-preview.1/Image-6.18.57-plb1) を入手します。preview.2でも同じImageを使います。
2. 「設定」→「検証済みゲストカーネルを読み込む」で選択します。既知のSHA-256・サイズと一致したファイルだけを専用領域へ保存します。別のビルドは拒否します。
3. Linuxの作業を保存し、VMプロファイルを選んで「適用」。最初は停止中のディスクをコピー・照合するため、端末の追加空き容量が必要です。
4. 切り替え後は標準ターミナルを開き直すか、Bridgeの全画面GUIを開きます。
5. 戻すときはMicrodroidを選んで適用します。元のDebianディスクを使います。

**実験用です。** ディスクなし起動、Debian・systemd・Binder、低負荷のCPU／GPU描画とTUN通信を確認しましたが、重いGUI/OpenGL処理でGunyahのメモリ提供が失敗しVMが終了する場合があります。初期値は512 MiB・1 CPU・CPU描画です。USB/xHCI・DRM・virtio-netなどのドライバーを含みます。直接USBはcrosvmが保護VMで無効にするため利用できません。Android 17は別の実験プロファイルで画面表示に対応しています。

ゲスト変更でもホスト障害の危険はゼロではありません。ホストのカーネル、SELinux、Gunyah保護機構は変更しません。[調査結果・対応範囲](docs/guest-kernel-plan.md)と[ソース・ビルド条件](kernels/README.md)を参照してください。

追加調査では、GPUなしのメモリ負荷や標準Microdroidカーネルでも同じ障害を確認しました。空きRAMがあるだけでは安定性を保証できず、現時点では未修正です。[Gunyah障害の調査記録](docs/gunyah-memory-investigation.md)と[Android 17の画面表示に向けた進捗](docs/android-guest-display.md)を公開しています。

## sudoとAndroid本体の保護

現在のDebianシェルはVM内のrootです。`sudo`は導入済みで、`sudo -n id`の成功を確認しています。一般ユーザーのsudoers設定は別途必要です。VM内のrootはAndroidのrootではありません。

AndroidのファイルやGPUデバイスをLinuxへ直接共有しません。GPUコマンド処理は非rootプロセスに分離しています。ただし、**現状のホストcrosvmはrootかつ標準プロセスサンドボックスなしで動く実験経路**です。pvmfwの検証済み起動・アテステーションもありません。悪意あるLinuxソフトからAndroid本体を完全に保護する用途には適しません。[保護境界と確認した制限](docs/security.md)を参照してください。

## 実験用ネットワーク

Linux 6.18のプロファイルで「連携」→「VM内のTUN通信を有効にする」をオンにし、通信元アプリを選んで適用します。VMを停止した後、GUIか標準ターミナルを開き直してください。初期状態はオフで、Microdroidでは従来のプロキシを使います。

TCP・UDP・DNSをVM内の仮想NICから中継するため、通常のアプリにプロキシ指定は不要です。IPv4／IPv6のHTTPS、Pythonの通常ソケット、UDP DNSを実機で確認しました。DNSは1.1.1.1／8.8.8.8を利用し、DNSファイルの変更はVMの起動中だけ有効です。

通信元の初期値は標準ターミナルです。Bridgeの全画面GUIを使う場合はBridgeを選べます。**選んだアプリのVPN・バックグラウンド通信制限に従います。** 実機では標準ターミナルが背景にあると通信を拒否され、前面では成功することを確認しています。Bridgeも背景やDozeでは制限される場合があります。Androidの通信制限を自動解除する機能ではありません。

「通信状態を更新」はVM内のTUNの状態を表示し、インターネット到達性の保証はしません。Linuxの `/tmp/plb-network.log` も確認できます。オフにしてVMを作り直すと、仮想NICと一時DNSは消えます。AndroidのNIC・経路・DNS・ファイアウォールは変更しません。

受信ポート公開、ブロードキャスト／マルチキャスト、任意のIPプロトコルは未対応です。`ping` は従来の実ICMP中継を使い、成功を装うローカル応答はしません。ハードウェアUSBの直接接続、GPU Vulkan、動画のハードウェア処理は引き続き未対応です。[試した経路と結果](docs/experimental-io.md)を公開しています。

## UDPとping

```sh
ping -c 4 1.1.1.1
plb-udp-forward 5353 1.1.1.1 53
```

`ping` はホスト側の非特権ICMPソケットを使って実際のIPv4 echoを送ります。表示するRTTにはVMとの転送時間も含みます。IPv6 pingやrawソケットは提供しません。Androidがping用ソケットを禁止している環境ではエラーになります。システム設定を変えて解除しません。

`plb-udp-forward` はゲストの `127.0.0.1:5353` に届くUDPを `1.1.1.1:53` へ転送します。利用するツール側もこのローカルポートへ接続する設定が必要です。別シェルタブで実行し、Ctrl+Cで終了します。宛先のホスト名・ポートは変更できます。同時に最大16クライアント、無通信60秒で関連付けを破棄、1回最大30分です。

この明示的な転送コマンド自体は仮想NICではありません。一般のLAN上の別ホストには接続できますが、ホスト自身・loopback・link-local・multicastなどは拒否します。UDPの外部からの着信待受は作りません。

## 保存・終了

専用ディスクへの変更はVMを終了しても残ります。タブの `exit` はそのシェルを終了します。1つのタブを閉じても他のタブは継続します。全接続を閉じた後の継続は設定で選べます。ホームへ移動するだけでは終了しない場合があります。

「VMと起動支援を停止」で全セッションを終了できます。先に作業を保存してください。再利用時は起動支援を準備し、ターミナルを開き直します。一時rootが失われた場合は既存のroot環境を復旧してから準備してください。本アプリはroot化を実行しません。

アプリのデータ削除・アンインストールでは専用Linuxディスクも消えます。必要なファイルは先にバックアップしてください。標準ターミナルの元イメージは別に保持されます。

## 制限

| 項目 | 現状 |
|---|---|
| VM | RAM 512 MiB〜8 GiB、1〜8 CPU（端末の余裕で制限）。稼働時間・常駐を選択 |
| シェル | PTY 80×24、同時接続はGUIを含め最大12 |
| 保存 | 専用ディスク。1〜128 GiBへオフライン拡張・縮小、空き領域回収、復元用ディスク保持。追加空き容量が必要 |
| ネットワーク | 通常モードはプロキシ／明示的UDP／IPv4 echo。実験モードは任意でTCP・UDP・DNS用のVM内TUN |
| ホストへの影響 | 通信・メモリ・ストレージは消費します。ルート・DNS・ファイアウォール設定は変更しません |
| 通信制限 | 選択したAndroidアプリ（初期値は標準ターミナル）のUIDで通信し、アプリ別VPN・省電力制限に従います。バックグラウンドやDozeでは通信が止まる場合があります |
| GUI | 9解像度、15〜120 fps上限、全画面。OpenGLと画面表示はGPU化可能。取得・コピーはCPU。音声中継あり。GPU Vulkan・ハードウェア動画処理は未対応 |
| 動作維持 | 対話前の起動支援待機は最大30分。VM稼働時間は選択可能。プロセス終了やroot喪失後は準備し直す必要があります |

RAMの設定値は、安定して使える実メモリ容量の保証ではありません。大容量を実際に使うとGunyahのメモリ障害が起きる場合があり、現在も調査中です。[実機検証の範囲](docs/memory-working-set-probes.md)を公開しています。

開発用の別VMMでは、保護Linux VMの4 GiB全バイト検査が2回成功しました。追加の一時THP設定を明示的に許可した条件での結果で、Android／GPUでの動作は未検証です。アプリの通常設定には適用していません。[追加の検証記録](docs/preallocated-vmm-validation.md)を参照してください。

標準のディスク設定はこの専用ディスクに適用できないため無効にしています。LinuxパッケージのインストールはVMの中だけで行われます。

## 無効化・復旧

1. 作業を保存し「VMと起動支援を停止」。
2. 接続スイッチをオフにし、ターミナルを閉じる。
3. Vectorでも無効にすれば標準動作に戻ります。

元の標準ターミナルが非保護VM非対応で落ちる端末では、無効化しても標準機能が使えるとは限りません。未対応のOS更新後にフックが止まった場合も、カーネル変更などで無理に回避しないでください。
